1 · Deployment architecture and trust boundaries

Everything inside the dashed box runs as the user, on the user's machine. The model never runs locally: the Claude Code CLI sends conversation and tool results to the inference endpoint and receives tool calls back. Claude Desktop is not part of the system.

2 · One guarded tool call

What happens between the model asking for a command and the command running. The hook receives the full tool input as JSON on stdin, and its exit code decides. A block is not silent: the reason goes back to the model as the tool result, and the user is told what was blocked and why.

3 · Control stack and what each layer lets through

Controls grouped by where they are enforced, top to bottom from the most to the least mechanical. The right column is the residual: what a layer does not stop and therefore hands to the next one. The last layer's residual is the accepted risk.

After the patch: a positive command-word allowlist with no cd, readers limited to the project and the ingest scratch, git tree rewrites denied except checkout -b and switch -c, and a browser filter that also catches computed property access, eval, string timers and .click(). The patched self-test has 384 cases and must pass before the copy replaces the committed hooks. An enterprise deployment should not go live before that.
