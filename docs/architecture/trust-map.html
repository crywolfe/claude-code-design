Trust zones and gates of the hardened design workspace

Five zones, four boundaries. At every crossing the map answers one question: is this call stopped by code that runs before the tool does, or by a rule the model is trusted to keep? That distinction matters more than the zone labels. A hook blocks the call regardless of what the prompt says. A rule holds only while the model follows it.

What the map says. The hooks are tested by 287 cases. Every bypass the reviewer found spells a command or path in a way the regexes do not recognise. The policy rules work only if the model follows them. No code checks that it did. The three critical gaps have the same cause. The guard matches on spelling, and the shell accepts more spellings than the guard checks. The patch normalises each command before checking it. It adds a command allowlist, normalises paths, and rejects ANSI-C quoting. This map shows the committed hooks because the patch has not been run. To apply it, run the patched self-test from the user's shell. If it passes, copy the patched hooks over the committed ones.

Findings register

What the code reviewer confirmed against the committed hooks, and what stays open on purpose. Severity is the reviewer's. Status is where the fix stands today, which for most rows means written, not applied.

IDFindingSeverityStatus
G-01Quote the command name ("perl" -zzz, pe'r'l) and no name-anchored rule matches. The shell strips the quotes before running the command; the regex does not.Criticalpatch pending
G-02A ./ or // prefix turns a protected path into a string the protected-file list does not recognise. Same file, different spelling.Criticalpatch pending
G-03ANSI-C quoting ($'\x2e\x2e') hides .. and absolute paths inside byte escapes the guard never decodes.Criticalpatch pending
G-04Readers (cat, head, rg, …) can read any non-dotfile path on the machine. The dotfile rule protects credentials, not the rest of the home directory.Importantpatch pending
G-05git checkout <sha> -- . or git reset --hard restores an older, weaker hook, and the guard trusts whichever hook is on disk.Importantpatch pending
G-06The evaluate_script filter is a text denylist, and window["fe"+"tch"] is not matched. A denylist cannot list every way JavaScript can express a call.Importantpatch pending
G-07False positives: 2>&1 inside a pipeline and which node are blocked, so /doctor and both export preflights fail. A guard that blocks the documented workflow pushes users to work around it.Importantpatch pending
G-08The Bash(rm -rf /*) deny also matches the documented rm -rf /tmp/cd-ingest-… cleanup, per the reviewer, so ingest cannot delete its scratch directory.Importantmanual settings edit
G-09[^\n] in two regexes meant "not backslash, not n" rather than "not newline". Not exploitable, but it sits in a security regex and should be corrected.Minorpatch pending
R-01The evaluate_script filter stays best-effort after the patch. The real boundary is the URL scope: the browser only ever loads pages this repo generated, so a script the filter misses runs against a page this repo wrote.Residualaccepted
R-02The browser hook matches three tools. click, fill_form and upload_file are ungated, and no skill asks for them. Unguarded, and so far unused.Residualaccepted
R-03Every policy-only crossing depends on the model. Prompt injection through ingested content is contained, not detected: a hijacked session can still only do what the hooks allow.Residualby design
R-04The guard reads raw command text, so prose with a command name, a backtick, .. or > in it is blocked. While revising this page, a search for the literal string <title> was refused as a redirect. A usability cost, not a security gap. Use the Read or Grep tool for such text.Residualby design
R-05Hooks and settings are tracked files, so switching branches is the user's job, from their own shell. Until the patch is applied, G-05 lets a session bypass that rule.Residualby design

After the patch is applied: the command word must be on a positive allowlist and cd is not on it, readers only see the project and the ingest scratch, git can no longer rewrite the tree except through checkout -b and switch -c, and the browser filter also catches computed property access, eval, string timers and .click(). The patch README says its self-test has 384 cases. That number is the README's, not this page's: nobody has run it yet, and it has to pass before the copy replaces the committed hooks.
